1. El flujo completo en 30 segundos

Persona escribe qué + dónde → backend interpreta actividad y ubicación → consulta 3+ fuentes → integra territorio + normativa + trámites → devuelve orientación + mapa + fuentes → la IA permite repreguntar. La IA nunca inventa: solo resume lo respaldado.
Stack backend: Python + FastAPI + PostgreSQL/PostGIS. Geocodificación USIG. IA como capa de interpretación con respuestas citadas.
Regla de oro: cada bloque de respuesta indica su fuente oficial. Si una fuente no está disponible, se avisa y se muestra el resto.

2. Las fuentes: qué hacen y qué les pedimos

USIG — ¿DÓNDE es?

Geocodificación + territorio

Hace: convierte “Corrientes 2500” en dirección oficial + coordenadas, y describe la zona.

Por qué: sin ubicación no hay mapa, ni normativa, ni trámites. Es la puerta de entrada.

Obtenemos: dirección normalizada, latitud/longitud, comuna, barrio, comisaría, hospital, escuela.

  • Probar en vivo ↓
  • Buscar “Corrientes 2500” (normalizar)
  • Datos de la zona (Comuna 3, Balvanera)
  • Mapa interactivo de la Ciudad
  • Documentación de APIs USIG
Ciudad 3D — ¿QUÉ se permite?

Normativa urbanística + catastro

Hace: dice qué rubros y construcciones están permitidos en cada lote (mixturas, usos, edificabilidad).

Por qué: es la única que cruza actividad × ubicación (ej: cafetería en esa cuadra).

Obtenemos: categorías de uso, rubros permitidos, mixtura del lote, edificabilidad, afectaciones.

  • Probar en vivo ↓
  • Visor Ciudad 3D
  • Categorías de uso (Comercial, Servicios…)
  • Rubros comerciales permitidos (ejemplo)
BA Data — ¿QUÉ contexto hay?

Catálogo de datos abiertos

Hace: reúne cientos de datasets de la Ciudad (locales, servicios, catastro, tablas y mapas).

Por qué: aporta contexto para enriquecer la respuesta (qué hay en la zona).

Obtenemos: tablas y archivos para cargar en nuestra base y mostrar contexto.

  • Probar en vivo ↓
  • Portal BA Data
  • Estado de la API
  • Lista de datasets
  • Ejemplo: dataset “datos útiles”
Trámites — ¿CÓMO lo habilito?

Guía oficial paso a paso

Hace: explica requisitos, documentación y pasos (habilitación común, exprés, licencias).

Por qué: construye el camino feliz accionable. Sin esto solo mostramos datos sueltos.

Obtenemos: pasos ordenados, requisitos, documentación y enlaces oficiales.

  • Probar en vivo ↓
  • Guía: cómo habilitar tu local
  • Habilitación de actividad económica
  • Habilitación exprés (locales chicos)

3. Cómo se complementan

USIG (dónde: punto + barrio)
   │ punto ─────────────────▶ Ciudad 3D (qué se permite: rubros)
   │ barrio/zona             │ rubro cafetería
   ▼                         ▼
BA Data (contexto) ───▶ Trámites (cómo: pasos + requisitos)
                            ▼  Respuesta: mapa + pasos + territorio + fuentes

Ejemplo Corrientes 2500: USIG ubica el punto en Balvanera, Comuna 3 → Ciudad 3D indica rubros comerciales permitidos → BA Data suma contexto de la zona → Trámites arma la guía (cuenta miBA → autorización → certificado ambiental).

4. Reparto de tareas: Análisis de Datos vs Backend

El equipo de Análisis de Datos define qué dato vale y cómo se lee; el Backend lo convierte en sistema en vivo (base, servicios, mapa, IA). Datos no programa ni mantiene la plataforma; Backend no decide el criterio del dato.

📊 Análisis de Datos — hasta acá

✔ Elegir qué datasets y capas sirven para la cafetería y cuáles no.
✔ Revisar calidad: estructura, nulos, duplicados, formatos y fechas.
✔ Entregar archivos curados de muestra (CSV/Excel/GeoJSON) + diccionario de campos.
✔ Armar mapeos y reglas: ej. rubro Ciudad 3D → trámite que corresponde; tabla de equivalencias.
✔ Curar la guía de trámites (pasos, requisitos, docs + enlace oficial) en planilla.
✔ Definir casos esperados: 15–20 consultas con su respuesta correcta para validar la IA.
✔ Documentar origen, fecha, límites y transformaciones de cada dato.

⚙️ Backend — desde acá

✔ Diseñar la base (PostGIS), los ETL automáticos y la actualización periódica.
✔ Exponer todo como servicios en vivo: geocodificación, territorio, trámites, mapa, chat IA.
✔ Implementar las reglas de Datos en código + manejo de errores y caídas.
✔ Integrar la IA, la trazabilidad técnica y el despliegue.
✔ Rendimiento, seguridad y monitoreo.

6. Qué necesita cada área

📊 Análisis de Datos
Entregar por fuente: muestra curada + diccionario + mapeos + casos esperados + reporte de calidad y límites. Nada de APIs: su salida es el insumo que Backend automatiza.
🎨 UX/UI
Diseñar: barra “qué + dónde”, resultado en 3 bloques (pasos / territorio / mapa), sello de fuente por bloque, estados de carga, sin datos y fuera de alcance, repreguntas sugeridas.
💻 Frontend
Consumir los 6 servicios, mapa con punto + 1 capa, navegación respuesta ↔ mapa ↔ fuentes, y manejo de respuestas parciales.
🧪 QA / Testing
Casos: camino feliz “cafetería Corrientes 2500”, dirección inexistente o ambigua, consulta fuera de alcance. Validar coordenadas, trazabilidad y que la IA cite fuentes.
📋 PO
Alcance MVP: 1 rubro, 3 fuentes integradas, 1 camino feliz completo. Criterio de aprobación: recorrido sin errores críticos y con fuentes visibles.
